# Vercel Deployment Guide

**Customer Support Copilot — synthetic-data demonstration deployed to Vercel.**

> ## ⚠️ READ THIS BEFORE DEMONSTRATING
>
> This deployment is a **demonstration environment only**.
>
> - **All customer data is synthetic.** Customers, agents, timelines, activity records and
>   audit entries are generated by a deterministic in-process seed. No real person, account or
>   social profile is represented. Every record carries `isSynthetic: true`.
> - **All application state is ephemeral.** State lives in module-level memory inside a single
>   serverless instance (`src/server/data/db.ts`, `drafts.ts`, `audit.ts`).
> - **Vercel serverless instances restart and scale.** Instances are cold-started, recycled after
>   idle time, and multiple instances serve traffic in parallel. Captured interactions, AI drafts,
>   edits, logged activities and the audit trail are **lost** when an instance is replaced, and two
>   consecutive requests are **not guaranteed to reach the same instance**.
> - **This is not production-ready.** A multi-request demo flow (capture → generate → edit → log)
>   only works while one warm instance serves it. A cold start or a load-balancer switch mid-flow
>   will 404 and the data will vanish.
> - **Persistent storage is required before any production use.** Replace the in-memory modules
>   with a real datastore (Vercel KV / Postgres / etc.) and move the audit trail to durable,
>   append-only storage.
> - **No AI provider, no CRM, no outbound messaging.** AI is deterministic mock output, nothing is
>   ever sent to a customer, and nothing is ever written to a CRM.
>
> **Ephemeral demo state — persistent storage required for production.**

---

## 1. Architecture

```
Browser
  │  HashRouter (#/dashboard, #/customers, #/audit) — no server round-trip for client routes
  │  relative fetch('/api/...')  — same origin, no CORS
  ▼
Vercel Edge / CDN
  ├── /api/*                → Node serverless function  (api/index.ts)
  ├── /assets/*  fingerprinted JS/CSS  → static, served from outputDirectory
  └── /*  everything else   → rewrite to /index.html   (SPA fallback)
                                │
                                ▼
              api/index.ts  ── serverless-http ──►  Express app (createApp())
                                                          ├── express.json (100kb)
                                                          ├── requestLogger
                                                          ├── /api  → apiRouter (all business logic)
                                                          └── static + SPA fallback  (local only)
                                                                │
                                                                ▼
                                       in-memory modules  →  db.ts / drafts.ts / audit.ts
                                       (EPHEMERAL — lost on cold start or instance switch)
```

**What is served by what**

| Request | Handled by | Notes |
|---|---|---|
| `/api/health`, `/api/dashboard`, `/api/customers`, … | Vercel function `api/index.ts` | Single function; all routes live in one router |
| Unknown `/api/*` | Same function | JSON `404 NOT_FOUND` — never falls through to `index.html` |
| `/assets/index-<hash>.js` | Vercel CDN | Fingerprinted by Vite; served from `outputDirectory` |
| `/`, `/anything-else` | Rewrite → `/index.html` | SPA fallback. HashRouter means real navigation stays client-side |

**Design decisions**

1. **The Express app is built by a factory, `createApp()` in `src/server/app.ts`.** The
   serverless entry point and the local dev entry point both call it, so local and deployed
   behaviour is identical by construction. `src/server/index.ts` (local) adds only `app.listen`.
2. **`src/server/api/routes.ts` is untouched and still reusable.** No route was rewritten, moved or
   renamed for the deployment. `apiRouter` is mounted at `/api` exactly as before.
3. **One serverless entry point (`api/index.ts`)** rather than one function per endpoint. Vercel maps
   every `/api/*` request to it. Business logic stays in one place.
4. **Static assets are resolved from `app.ts`'s own location**, never from the entry point, so
   wrapping the app for Vercel cannot change the asset path. On Vercel the function skips static
   serving entirely (`VERCEL` is set, the bundle contains no `dist/`) because Vercel serves
   `outputDirectory` and applies the SPA rewrite itself.
5. **`app.listen()` is not called in the function.** Vercel requires an exported request handler.

## 2. Deployment setup

### 2.1 Prerequisites

- Node.js **22.x** (pinned via `.nvmrc` and `functions.runtime` in `vercel.json`).
- A Vercel account and the [Vercel CLI](https://vercel.com/docs/cli) (`npm i -g vercel`).
- No secrets and no environment variables are required. See §5.

### 2.2 Local commands

```bash
npm install
npm run build      # vite build -> src/ui/dist  (UI only; the function runs from source)
npm start          # local Express server on :8787, also serves src/ui/dist
npm run dev        # API :8787 + Vite dev server :5173 with /api proxy
npm test           # vitest run (35/35)
npm run lint
npm run typecheck
```

`npm run build` produces the **UI only**. The serverless function is transpiled by Vercel's Node
builder at deploy time; there is no separate server compile step.

### 2.3 Deploy

```bash
vercel                 # first deploy (preview)
vercel --prod          # production deploy
```

Or import the repository at [vercel.com/new](https://vercel.com/new) and use the settings in §4.

### 2.4 What gets deployed

- Function: `api/index.ts` → `/api/*`
- Static output: `src/ui/dist` (git-ignored; produced by the build command)

## 3. Vercel configuration

`vercel.json` (committed, authoritative):

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "version": 2,
  "installCommand": "npm install",
  "buildCommand": "npm run build",
  "outputDirectory": "src/ui/dist",
  "functions": {
    "api/index.ts": {
      "runtime": "nodejs22.x",
      "maxDuration": 30
    }
  },
  "rewrites": [
    { "source": "/((?!api/).*)", "destination": "/index.html" }
  ]
}
```

| Key | Value | Why |
|---|---|---|
| `buildCommand` | `npm run build` | Builds the Vite UI into `src/ui/dist`. Seed data is committed, so no seed step is needed. |
| `outputDirectory` | `src/ui/dist` | Vercel serves these files from the CDN. |
| `installCommand` | `npm install` | `serverless-http` is a runtime dependency. |
| `functions["api/index.ts"].runtime` | `nodejs22.x` | Pins the function runtime; matches `.nvmrc` and `engines.node`. |
| `functions["api/index.ts"].maxDuration` | `30` | Well within the Node plan limit; this app needs no long compute. |
| `rewrites` | `/((?!api/).*)` → `/index.html` | SPA fallback that explicitly excludes `/api`. |

### Why the rewrite is correct

Vercel resolves a request in this order: **redirects → headers → filesystem → rewrites → 404.**

1. `/api/health` matches the filesystem phase (the `api/index.ts` function) and is answered by the
   function. The rewrite never sees it, and the `(?!api/)` guard makes that explicit.
2. `/assets/index-<hash>.js` matches a real file in `outputDirectory` and is served as a static
   asset. Fingerprinted filenames are never rewritten to `index.html`.
3. Anything else falls through to the rewrite and gets `index.html`, so the SPA boots.

Because the UI uses **HashRouter**, the fragment (`#/customers`) is never sent to the server. Deep
links such as `/#/customers/c-001` and `/#/audit` are a single request for `/` and resolve entirely
in the browser. The rewrite exists as safety for direct hits on unknown paths, not for routing.

## 5. Environment variables

| Variable | Set on Vercel? | Notes |
|---|---|---|
| `PORT` | **No — do not set it.** | Vercel manages ports. The zod default `8787` is local-dev only, and the function never calls `app.listen`. |
| `NODE_ENV` | No | Vercel sets `production`, which is a valid value in the schema. |
| `AI_PROVIDER` | No | The schema is `z.enum(['mock'])`. Any other value makes config validation fail and the process exit — the app cannot be started with a real provider. |
| `AI_API_KEY` | **No — must stay unset.** | See below. |
| `VERCEL` | Set automatically by Vercel | Used only to detect the serverless runtime so the function skips static serving. |

### AI fails closed

This build is **mock-only** and contains no AI SDK, no provider client and no outbound AI call.

If `AI_API_KEY` is accidentally set, the application **fails closed** rather than silently using it:

- the key is **never read or transmitted** by any code path;
- `config.ai.mode` becomes `'blocked'` instead of `'external'`;
- every draft-generation endpoint returns **`501 AI_UNAVAILABLE`** with a message naming the ignored key;
- a warning is printed on cold start;
- `GET /api/health` reports `ai: { "mode": "blocked", "configured": true, "keyIgnored": true }` so the
  misconfiguration is visible without reading logs.

The fix is to remove `AI_API_KEY` from the Vercel project environment; the app then returns to
`ai.mode: "mock"`.

## 6. Routing

| Path | Result |
|---|---|
| `GET /api/health` | `200` service health + record counts + AI mode |
| `GET /api/dashboard` | Dashboard aggregates |
| `GET /api/customers?search=&channel=&limit=&offset=` | Customer list (synthetic) |
| `GET /api/customers/:id` | Customer detail + activity timeline |
| `POST /api/customers/:id/interactions` | Capture an interaction → `201` |
| `GET /api/interactions/:id` | Interaction detail |
| `POST /api/interactions/:id/summarize` | AI summary draft (mock) |
| `POST /api/interactions/:id/generate-note` | AI CRM note draft (mock, advisory only) |
| `POST /api/interactions/:id/generate-response` | AI suggested response (mock, advisory only) |
| `GET /api/interactions/:id/drafts` | Current drafts |
| `PUT /api/interactions/:id/drafts/:draftId` | Edit a draft → new revision |
| `POST /api/interactions/:id/log` | Log activity after explicit human approval → `201`; `409 ALREADY_LOGGED` on repeat |
| `GET /api/agents` | Synthetic agent list |
| `GET /api/audit?limit=` | Audit entries |
| `GET /api/anything-else` | JSON `404 NOT_FOUND` |

Client routes are all under the hash: `/#/dashboard`, `/#/customers`, `/#/customers/:id`, `/#/audit`.
The UI fetches relative `/api/...` URLs, so there is no CORS configuration and no API base URL to set.

## 7. Ephemeral-state limitation

> **Ephemeral demo state — persistent storage required for production.**

**This is the most important operational caveat of the deployment.**

All runtime state is held in module-level variables:

| Module | State | Consequence of a restart |
|---|---|---|
| `src/server/data/db.ts` | Generated seed snapshot, captured interactions, logged activities | Captures and logged activities disappear; seed regenerates identically |
| `src/server/data/drafts.ts` | AI drafts and revisions | Drafts and edits disappear |
| `src/server/data/audit.ts` | Audit trail | Audit history disappears |

What this means in practice:

- The synthetic seed regenerates deterministically, so the dashboard always looks populated. That
  is the only state that reliably survives a cold start.
- Anything a user does in the demo — capturing an interaction, generating a draft, editing it,
  logging an activity — exists **only in that one instance's memory**.
- A Vercel function instance is recycled after a period of inactivity. A demo left open overnight
  will come back to a fresh instance.
- With more than one instance serving traffic, two requests in the same flow can land on different
  instances. The second request will not see the first request's work, and the UI will show a
  `404` for the interaction or draft.
- `Date.now()`-based IDs reset on restart, so IDs may repeat across instances.

**Guidance**

- Demonstrate the end-to-end flow in a single continuous session, on one instance.
- If a flow breaks with a `404`, that is expected behaviour, not a bug: the instance restarted.
  Reload the page and start the flow again.
- **Before production use, replace all three modules with a persistent datastore** and make the audit
  trail append-only and durable. No amount of serverless configuration substitutes for storage.

## 8. Security checklist

- [x] **No secrets in the repository.** No `.env` file, API key or credential is tracked; `.env`,
      `.env.*`, `server/.env` and `*.log` are git-ignored.
- [x] **No real AI provider.** `AI_PROVIDER` is `z.enum(['mock'])`; any other value aborts startup.
- [x] **Fail closed on a stray key.** `AI_API_KEY` is ignored, `mode` becomes `blocked`, generation
      returns `501 AI_UNAVAILABLE`, and health reports `keyIgnored`.
- [x] **No CRM integration and no outbound messaging.** Nothing in the codebase opens an outbound
      connection for customer contact. CRM notes and suggested responses are stored locally as
      advisory text only.
- [x] **Synthetic data only.** Every record carries `isSynthetic: true`; the seed generator produces
      fictional names, handles and locations.
- [x] **Human approval is mandatory.** The log endpoint is only reachable after the operator
      explicitly confirms review in the UI, and the server re-validates state before logging.
- [x] **Duplicate protection.** Re-logging an interaction returns `409 ALREADY_LOGGED`.
- [x] **Input validation on every boundary.** zod schemas validate request bodies, query strings,
      responses and AI output; `express.json` is limited to 100 kB.
- [x] **No information leaks.** `x-powered-by` is disabled; errors return
      `{ error: { code, message } }` with no stack traces; unknown API paths return JSON 404.
- [x] **No CORS wildcard.** The UI is same-origin, so no cross-origin policy is configured.
- [x] **Pinned runtime.** `nodejs22.x` in `vercel.json` and `.nvmrc` prevent surprise runtime
      upgrades.
- [ ] **Run `npm audit` before each deploy** and patch `express`, `react`, `zod`, `vite`.
- [ ] **Keep the demo public-read-only aware.** This demo has **no authentication** — the API is
      open to anyone with the URL and anyone can capture, generate and log synthetic activity. Do not
      put it behind real data, and do not expose it publicly without adding access control.
- [ ] **Re-verify the environment indicator** is visible in the top bar and sidebar after any UI
      change: *"Demo Environment • Synthetic Data • No CRM Connection"*.
